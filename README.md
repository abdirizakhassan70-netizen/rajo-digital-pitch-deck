Exercise A: Explaining the Software Development Life Cycle (SDLC)
Prompt 1: Zero-Shot Prompting
1. Your prompt
Explain the Software Development Life Cycle (SDLC) using simple English. Describe its key stages and explain why it is important for software development.
2. AI Response
The Software Development Life Cycle (SDLC) is a step-by-step process used to develop high-quality software. It helps developers plan, design, build, test, and maintain software systems.
The main stages of the SDLC are:
Planning: Identifying project goals, resources, costs, and timelines.
Requirements Analysis: Understanding what users need from the software.
System Design: Planning how the software will look and function.
Implementation: Writing code and developing the software.
Testing: Checking the software for errors and ensuring it functions correctly.
Deployment: Releasing the software to users.
Maintenance: Updating the software and fixing issues after its release.
The SDLC is important because It helps developers organize their work, reduce errors, save time, and produce reliable software.
3. Summary (3–5 sentences)
The SDLC is a process used for the systematic development of software. It consists of several stages, including planning, requirements analysis, design, implementation, testing, deployment, and maintenance. Each stage serves a specific purpose. The SDLC helps developers produce high-quality, reliable software.

Exercise B: Software Development Models
1. Your Prompt
Act as an experienced software engineering instructor. Explain the most suitable software development model for each of the following four project scenarios. Use simple English appropriate for university students who are just starting out.

1. A project with stable and clearly defined requirements.

2. A project where requirements change frequently based on user feedback.

3. A large-scale project involving significant technical and security risks.

4. A project where testing and verification are critical.

For each scenario:

* Recommend the most appropriate software development model.
* Explain why this model is suitable.
* State one limitation of the model.

Use clear headings and effective explanations. Conclude with a brief summary comparing the models.
Use clear headings and effective descriptions. Conclude with a brief summary that compares the models.
2. AI Response
Scenario 1: A project with stable and clearly defined requirements
Recommended Model: Waterfall Model
Why it is suitable:
The Waterfall model is appropriate because the project requirements are clearly defined and unlikely to change. It follows a step-by-step approach, including planning, requirements analysis, design, implementation, testing, and maintenance.
Limitation: Making changes after a phase has been completed is difficult and costly.
Scenario 2: A project where requirements change frequently based on user feedback
Recommended Model: Agile Model (Scrum)
Why it is suitable:
Agile is suitable because it allows developers to make changes based on customer feedback. The team develops the software in small segments—known as 'iterations' or 'sprints'—and continuously improves the product.
Limitation: Frequent changes can make project planning and cost estimation difficult.
Scenario 3: A large project with significant technical and security risks
Recommended Model: Spiral Model
Reason for suitability:
The Spiral Model is suitable because it focuses on identifying and managing risks throughout the software development process. It allows developers to assess technical challenges, security risks, and potential solutions during each development cycle.
Limitation: It can be costly and requires experienced professionals to manage the risks.
Scenario 4: A project where testing and verification are critical
Recommended Model: V-Model (Verification and Validation Model)
Reason for suitability:
The V-Model is suitable because testing and verification are planned at every stage of development. Each development activity has a corresponding testing activity, which helps developers identify issues early on.
Limitation: It lacks flexibility when requirements change during development.
Summary
Different software development models are suited to different project needs. The Waterfall model works well with stable requirements, Agile supports changing requirements, the Spiral model focuses on risk management, and the V-Model emphasizes testing and verification. Choosing the right model contributes to improving software quality and project success.
3. Reflection
Through this exercise, I learned that the choice of a software development model depends on the characteristics and requirements of the project. Each model has its own unique advantages and limitations. The Waterfall model is effective when requirements are stable; Agile is suitable when changes occur frequently; the Spiral model is useful for projects involving significant risks; and the V-Model is appropriate when testing and verification are critical. Therefore, software engineers must carefully understand the project's needs before selecting a development model.
